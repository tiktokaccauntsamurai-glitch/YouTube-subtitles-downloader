## Requirements

- Windows (uses the Windows registry to find your real `Downloads` folder; falls back to `~/Downloads` elsewhere).
- Python 3.8+.
- The `yt-dlp` package — the only dependency, everything else is the Python standard library.

## Install

```
python -m pip install -U yt-dlp
```

## Run

Double-click `run.bat` (it installs yt-dlp automatically if missing), or:

```
python yt_subs.py
```

The program then only waits for a link — a video or a playlist. Empty line or `q` to quit.

One-shot, no prompt (you can pass several links at once, they're processed one after another):

```
python yt_subs.py "https://www.youtube.com/watch?v=VIDEO_ID"
python yt_subs.py "https://www.youtube.com/playlist?list=PLAYLIST_ID"
python yt_subs.py "LINK_1" "LINK_2" "LINK_3"
```

A channel link also works and is treated like a playlist of all its videos:

```
python yt_subs.py "https://www.youtube.com/@channelname"
```

## How language & track selection works

Every video has up to two kinds of subtitles per language: **manual** (written by the uploader or a translator) and **automatic** (generated by YouTube's speech recognition). The program picks exactly one track using these rules, in order:

1. **Detect the video's native language** — from YouTube's own `language` metadata field, or (if that's missing) from the auto-caption track whose code ends in `-orig` — YouTube tags the auto track built from the video's original audio this way, which is the most reliable signal for multi-language videos with several dubs. If neither exists but the video has exactly one manual subtitle track, that track's language is assumed to be native. Otherwise it defaults to English.
2. **Pick the target language** — `ru` if the native language is Russian, `en` for every other native language. (This is exactly the setting `--lang` lets you override — see the next section.)
3. **Prefer manual subtitles in the target language**, if they exist.
4. **Otherwise, use automatic subtitles in the target language.** Importantly: if manual subtitles exist but are in some *other* language, they are skipped in favor of automatic subtitles in the target language — manual subtitles only "win" when they actually match the target language.
5. **If the target language doesn't exist in any form** (neither manual nor automatic), fall back to the video's native language: manual first, then automatic.
6. **If even that doesn't exist**, take whatever manual or automatic track is available, in that order.

### Worked examples

| Video's native language | Target language | Manual tracks available | Automatic tracks available | What gets downloaded |
|---|---|---|---|---|
| Russian | ru | ru, en | ru, en | **manual ru** (rule 3) |
| Russian | ru | en only | ru, en | **automatic ru** (rule 4 — manual en is skipped, it's not the target) |
| English | en | en | en | **manual en** (rule 3) |
| German | en | de only | de, en | **automatic en** (rule 4 — manual de isn't the target) |
| German | en | de, en-US | de | **manual en-US** (rule 3 — region code `en-US` still matches target `en`) |
| Japanese | en | ja only | ja only | **manual ja** (rule 5 — no English exists at all, fall back to native) |

## Fixing/overriding the preferred language

By default the target language is always **ru for Russian videos, en for everything else** — this is intentional and covers the common case, but it's not the only language you might want. Use the `--lang` flag to force a specific target language for a run, overriding the ru/en default entirely:

```
python yt_subs.py --lang fr "https://www.youtube.com/watch?v=VIDEO_ID"
python yt_subs.py --lang es "https://www.youtube.com/playlist?list=PLAYLIST_ID"
```

`--lang` accepts any language code YouTube uses for subtitles (`fr`, `es`, `de`, `ja`, `pt`, ...; a region suffix like `pt-BR` also works and is matched by its base language). Once set, the priority rules above still apply exactly the same way — manual in that language first, then automatic in that language, then a native-language fallback if the requested language isn't available at all.

`--lang` works in both modes: pass it once on the command line for a one-shot run, or pass it before starting interactive mode (`python yt_subs.py --lang de`) and it applies to every link you paste in that session. It doesn't currently prompt for a per-link language — if you need different languages for different links, run the program again with a different `--lang`.

If you want to change the *default* ru/en behavior permanently instead of passing `--lang` every time, that's a one-line source edit in `yt_subs.py`, in `choose_track()`:

```python
target = base_lang(target_lang) if target_lang else ("ru" if native == "ru" else "en")
```

Replace the `"ru" if native == "ru" else "en"` part with whatever default logic you want.

## Full command-line reference

```
python yt_subs.py [urls ...] [--out FOLDER] [--no-ts] [--cookies BROWSER_OR_FILE] [--lang CODE] [--reset-settings]
```

| Flag | Default | What it does |
|---|---|---|
| `urls` (positional, optional) | — | one or more video/playlist/channel links; if omitted, the program starts the interactive prompt instead |
| `--out FOLDER` | last saved, or your Windows `Downloads` folder | save `.md` files here instead — remembered for next time, see [below](#persisted-settings) |
| `--no-ts` | off (timestamps shown) | strip the `**[mm:ss]**` timestamp prefix from every paragraph, leaving plain text (not remembered — pass it each time you want it) |
| `--cookies BROWSER_OR_FILE` | last saved, or none | a browser name (`chrome`, `edge`, `firefox`) to pull a signed-in session's cookies from, or a path to an exported `cookies.txt` file — needed when YouTube demands sign-in (age-restricted, some private/members-only videos, or a bot check); remembered for next time |
| `--lang CODE` | last saved, or none (ru/en auto-detected) | override the target language — see [above](#fixingoverriding-the-preferred-language); remembered for next time |
| `--reset-settings` | — | forget the saved `--out`/`--cookies`/`--lang` and exit immediately (no link needed) |

## Persisted settings

`--out`, `--cookies`, and `--lang` are remembered between runs, so you don't have to retype the same browser name or output folder every single time:

- Pass a flag explicitly → it's used for this run **and** saved as the new default.
- Omit a flag → the last saved value is reused automatically (the program prints a line like `Using saved --cookies: firefox` so it's clear where the value came from).
- Run `python yt_subs.py --reset-settings` to forget everything that was saved and start clean.

Settings are stored in a small JSON file outside the project folder — `%APPDATA%\yt_subs\settings.json` on Windows (`~/.config/yt_subs/settings.json` elsewhere) — so they survive updating or moving `yt_subs.py`, and they're never part of the git repo. Only the `--cookies` *setting* is remembered (e.g. the word `chrome` or a file path) — actual cookie values are never read into this file or stored by the program at all; they're pulled live from the browser (or from your `cookies.txt`) by yt-dlp on every run, exactly like when you pass `--cookies` by hand. `--no-ts` is a plain per-run flag and isn't persisted.

## Where files go and what they look like

- A single video: `Downloads\Video title [videoID].md`
- A playlist or channel: `Downloads\Playlist title\Video title [videoID].md` — one file per video, unavailable ones are skipped.

Each file starts with a metadata header, then the subtitle text:

```markdown
# Video title

- **Link:** https://www.youtube.com/watch?v=VIDEO_ID
- **Channel:** Uploader name
- **Published:** 2024-01-15
- **Duration:** 12:34
- **Video language:** en
- **Subtitles:** en (manual)
- **Downloaded:** 2026-09-05 19:02

---

**[00:00]** First paragraph of subtitle text, merged from
several short cues into readable sentences...

**[01:47]** Next paragraph, starting after a natural pause
in speech or at the end of a long sentence...
```

Paragraphs are merged automatically from the raw, few-seconds-long subtitle cues so the text reads naturally instead of as a long list of timestamps — a new paragraph starts on a long pause in speech, a natural sentence break once a paragraph is a reasonable size, or a hard length limit if neither happens for a while. Pass `--no-ts` to drop the `**[mm:ss]**` prefixes and get plain flowing text instead.

## What won't download

- Videos with no subtitles at all (author disabled them, and auto-generation didn't kick in).
- Private, deleted, age-restricted (18+), and region-blocked videos — without `--cookies`.
- Live streams still in progress (subtitles appear only after they end) and premieres that haven't started.
- Unavailable videos inside a playlist/channel are skipped individually — the rest still download, with a final "Done: N of M" counter and a per-video reason printed for each skip.

## Troubleshooting

If YouTube starts complaining, first try updating yt-dlp — YouTube's anti-automation defenses change often, and the maintainers usually ship a fix quickly:

```
python -m pip install -U yt-dlp
```

**"YouTube is asking to confirm you're not a bot"** — run with `--cookies chrome` (or `firefox`/`edge`) so the request carries a signed-in session.

**"Failed to decrypt with DPAPI"** when using `--cookies chrome` — since Chrome 127+, Google encrypts cookies with a new scheme (App-Bound Encryption) that sometimes can't be decrypted even with the browser fully closed. Options, in order of convenience:
1. Fully close Chrome (check Task Manager for lingering background processes) and try again.
2. Use `--cookies firefox` instead — Firefox doesn't have this issue.
3. Export `cookies.txt` with a browser extension (e.g. "Get cookies.txt LOCALLY") and pass the file path: `--cookies "C:\path\to\cookies.txt"`.

**"The page needs to be reloaded"** even with cookies working — a known YouTube/yt-dlp bug ([yt-dlp#17389](https://github.com/yt-dlp/yt-dlp/issues/17389)) where the default client set for signed-in sessions includes a currently-broken client (`tv_downgraded`). The program already works around this by excluding it; if it still happens, update yt-dlp, or try the same link without `--cookies` — most videos that don't require sign-in download fine either way.

**"Requested format is not available"** — the program explicitly ignores this class of error (it doesn't need video/audio formats, only subtitles), so if you see it anyway, it likely means yt-dlp itself needs an update.

For everything else, the error message printed by the program is usually specific enough to act on directly (private video, region-blocked, live event not over yet, etc.) — see the full list of recognized errors in [HOW_IT_WORKS.md](HOW_IT_WORKS.md#8-turning-errors-into-something-readable-short_error).

## Security notes

**Cookies are effectively a copy of your login — guard them like a password.** `--cookies` hands yt-dlp full access to your browser session for that domain, and a `cookies.txt` export can even contain cookies for every site you're logged into, not just YouTube. So:

- Never commit a `cookies.txt` file (it's already listed in `.gitignore`), never paste it into chats or bug reports, and keep it outside the project folder if you export one.
- Only the *setting* (a browser name, or a file path) is remembered by [persisted settings](#persisted-settings) — never the cookie values themselves.
- If a `cookies.txt` ever does leak or end up in git history, treat the session as compromised: sign out everywhere / change the password, rather than assuming deleting the file is enough.
- Consider a separate, non-critical Google account if you plan to run this often or at volume against `--cookies`-gated content — so a leak or a block never touches your main account.

**Avoid IP throttling/bans on large playlists.** YouTube can respond with `HTTP 429` (soft rate-limit) if it sees heavy automated traffic from one IP. To stay under the radar:

- Downloading a playlist already adds a random 1–3 second delay before each video, so requests don't go out back-to-back; for playlists over 50 videos the program prints a heads-up that this will take longer because of it.
- Prefer processing very large channels/playlists in a few smaller sessions rather than thousands of videos in one uninterrupted run.
- Don't run several copies of the script in parallel against the same IP/account — that reads as obvious automation.
- Keep yt-dlp updated (`python -m pip install -U yt-dlp`); it and YouTube are in a constant back-and-forth, and staying current is the single biggest thing that keeps this tool working.
